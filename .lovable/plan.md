# Консультация для ТЗ: размещённые товары YORSO

Это совет для дальнейшей реализации. Код, данные и сборка не менялись. Готовность не подтверждаю, локальный код новее моей копии.

## 1. Разделение понятий (главный риск)
- «Ассортимент» (`/account/products`): что компания покупает или продаёт. Без цен, только для профиля и подбора.
- «Товарные предложения» (новый раздел, например «Продажи → Предложения»): опубликованная карточка с ценой, базисами и ступенями цен. Её видят покупатели в `/offers` и подбор в CRM-сделке.
- В интерфейсе разные названия, разные пункты меню и разные пустые состояния. На карточке ассортимента ссылка «Создать предложение по этому товару» с предзаполнением вида. Обратной автосвязи нет.

## 2. Список предложений
- Вкладки статуса: «В продаже», «Готово к публикации», «Черновики», «Архив» (последнее решает владелец), счётчики приглушённые.
- Вкладки соединены с панелью: фон активной вкладки = фон панели, нижней границы нет, сверху полоса primary 2px, неактивные с приглушённым текстом без фона, hover = muted, фокус = оранжевое кольцо. На 390px вкладки прокручиваются горизонтально и не обрезаются.
- Одна строка инструментов: поиск (применяется по Enter или кнопке-лупе), фильтр состояния (замороженный / свежий и т. д.), сортировка «Изменено». Кнопка «Создать предложение» справа.
- Строка таблицы, высота около 56px: товар (коммерческое название + латинское название курсивом под ним) · состояние/вид разделки · цена за единицу по базису по умолчанию + «ещё N базисов» · МОК · изменено · действия (меню «⋯»: Изменить, Снять с публикации / Опубликовать, В архив).
- Быстрое редактирование цены в строке — только для одного базиса и одной ступени. Если ступеней несколько, ссылка ведёт в карточку на вкладку «Цены». Сохранение явное (Enter / галочка, Esc отменяет), статус в строке.
- Мобильная версия: компактная запись (название, латинское название, цена, статус, «⋯» 44×44), без горизонтальной таблицы.

## 3. Полная карточка: секции (вкладки, соединённые с панелью)
1. **Товар**: коммерческое название*, латинское название* (из справочника видов), тип производства* (21 значение, единый справочник), вид разделки*, производитель, страна происхождения, описание.
2. **Вылов и производство**: способ вылова*, орудие лова, район ФАО, дата производства/вылова, срок годности, место и дата поступления.
3. **Характеристики**: размер, вес упаковки, хранение, состав, обработка/презентация, пищевая ценность на 100 г (4 поля в одной строке, на mobile 2×2).
4. **Медиа**: изображения, видео; первое изображение — обложка.
5. **Условия и цены**: единица* (kg/t/g/pcs), МОК*, способ оплаты + описание, сертификаты (общий выбор сертификатов), варианты поставки (см. п. 4).
Сверху карточки одна строка: статус, «Изменено», ошибки по вкладкам (точка + число у вкладки с ошибками). Снизу закреплённая пара «Сохранить черновик» / «Отмена» и отдельное «Опубликовать».

Условные поля: орудие лова и район ФАО — только при способе «дикий вылов»; место/дата поступления — при наличии на складе; дата производства/вылова обязательна для замороженного или свежего — решает владелец. Список полей зависит от типа производства (Frozen и Fresh расходятся).

## 4. Варианты поставки и ступени цен без «простыни»
- Список вариантов поставки компактными строками: «Название · Инкотермс · Страна/регион · Валюта · Ступеней: N · от X». Один вариант отмечен по умолчанию.
- «Добавить вариант» и «Изменить» открывают боковую панель (на mobile — полноэкранный слой) с фиксированными шапкой и кнопками и прокруткой только содержимого: название*, Инкотермс*, страна*, регион, валюта* USD/EUR/CNY/RUB, остаток, ступени.
- Ступени цен — мини-таблица «Объём от · Цена за единицу», минимум одна строка, добавление и удаление в строке. Валидация: объёмы возрастают, первая ступень ≥ МОК, без пересечений, у цены 2 знака после запятой.
- «Дублировать вариант» для другого порта, без копирования между валютами и без конвертации.
- Страна и мета-регион — разные поля: страна только из списка стран, мета-регион отдельным необязательным выбором. Смешанный список не переносить.
- Инкотермс — только Incoterms 2020; DAT не показывать для новых карточек, в старых записях показывать «DAT (устаревший, замените на DPU)» только для чтения — решает владелец.

## 5. Mobile 390px и клавиатура
- Вкладки карточки прокручиваются горизонтально, активная видна, страница не прокручивается вбок.
- Поля в одну колонку, пары (единица + МОК, объём + цена) в две колонки, все элементы управления 44px.
- При открытой клавиатуре кнопки сохранения не закрывают поле в фокусе.
- Порядок Tab = визуальный; стрелки внутри вкладок; Esc закрывает панель варианта и возвращает фокус на «Изменить».
- Ошибка публикации переводит на первую вкладку с ошибкой и ставит фокус в поле.

## 6. Общий стиль
Светлые поля, оранжевый фокус, голубой выбранный пункт в CrmSelect; подписи обычным регистром, без uppercase-меток; без декоративных карточек и вложенных карточек.

## 7. Проверяемые UX-критерии
1. Ассортимент и предложения имеют разные названия разделов, и ни в одной строке нет формулировки, допускающей двойное толкование.
2. У активной вкладки нет линии между ней и панелью; оранжевый — только полоса 2px и фокус.
3. Строка списка ≤ 60px на компьютере; товар, цена и статус читаются без раскрытия.
4. Быстрое редактирование цены не появляется у предложений с несколькими ступенями или базисами.
5. «Опубликовать» недоступно, пока не заполнены обязательные поля; у вкладок есть счётчики ошибок.
6. Валидация ступеней: возрастающий объём, первая ступень ≥ МОК, сообщение у конкретной строки.
7. В выборе страны нет мета-регионов; DAT нельзя выбрать в новой карточке.
8. Не существует суммы или конвертации между валютами.
9. 390px и 320px: `scrollWidth === clientWidth`, элементы управления ≥ 44px.
10. Весь процесс создания проходит только с клавиатуры: фокус виден, Esc возвращает фокус.
11. Снятие с публикации и архив — с подтверждением; снятое предложение пропадает из подбора CRM-сделки.
12. Ошибка загрузки списка не выглядит как «Предложений нет».

## 8. Решения владельца
- Нужна ли вкладка «Архив» и восстановление из неё.
- Разница между статусами «Готово к публикации» и «Черновик» (кто переводит, нужна ли проверка модератором).
- Обязательность дат и условных полей по типу производства.
- Политика для DAT и старых значений стран/мета-регионов.
- Допускается ли несколько валют в одном предложении.
- Видимость остатка покупателю и уровни доступа к цене (сохраняется модель anonymous_locked / registered_locked / qualified_unlocked).

Вне объёма: корзина, оплата, ERP.
