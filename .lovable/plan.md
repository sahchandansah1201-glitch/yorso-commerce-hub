# Критика чек-листа синтетической приёмки (консультация)

Я не открывал и не проверял localhost, не читал код и данные проекта. Опираюсь только на придуманный сценарий из запроса. Эта консультация не может подтвердить приёмку.

## 1. Блокеры и ложно-зелёные ловушки
1. **Медиа «загрузилось» по HTTP 200 или миниатюре.** Нужно: у каждого из 3 фото `naturalWidth > 0` после `decode()`; у каждого из 2 видео `readyState ≥ 3` и `currentTime` растёт больше чем на 1 с после play. Если хоть один файл не прошёл — не принято.
2. **Тихая замена истёкшего базиса.** Если выбранный FOB истёк, а запрос ушёл по второму порту или по старой цене — ложный успех. Ожидание: явная ошибка «Условия истекли, выберите заново», без отправки.
3. **Успех диалога доступа без выдачи доступа.** Текст «Запрос отправлен» нельзя путать с доступом. Проверка: после закрытия диалога и перезагрузки точная цена по-прежнему скрыта, пока сервер не подтвердит выдачу.
4. **Старая цена при ошибке чтения товара.** Кэш или прошлое состояние, показанное как актуальное. Ожидание: состояние «Недоступно», без цены и без кнопки запроса.
5. **Повтор создаёт дубль.** Повтор того же запроса после неясного ответа должен вернуть ту же квитанцию; другой текст с тем же ключом — конфликт, а не вторая запись.
6. **Ответ «виден» только в рамках сессии.** Если ответ продавца есть только в памяти вкладки, это не приёмка. Нужна перезагрузка и вход второй стороной.

## 2. Проверки: ожидание / факт / доказательство

**A. Только чтение (после окна обслуживания)**
- Каталог, товар, поставщик у анонима: название полностью, публичные факты; точной цены и контактов нет. Доказательство: скриншоты + текст DOM без цифр 13700/13650 и без контактов.
- Медиа: см. блокер 1. Доказательство: таблица из 5 строк (файл, naturalWidth/Height или длительность, прирост currentTime).
- Ширины 1440/1024/768/390/320: `scrollWidth ≤ clientWidth`; кнопка не обрезана (её rect внутри экрана); заголовок и цена/её состояние видны без горизонтальной прокрутки. Доказательство: 5 скриншотов + замеры.
- Клавиатура: Tab доходит до всех действий, у каждого видимый фокус; Esc закрывает окна, фокус возвращается на кнопку, которая их открыла. Каждая видимая кнопка либо переходит куда-то, либо меняет состояние — запись результата.
- Отказ чтения (искусственный, на тестовой сборке): «Недоступно», без старых цен.

**B. Отдельно одобренный путь B ↔ A**
- Покупатель B выбирает один точный базис; квитанция показывает тот же порт, валюту, оплату, ступень (24 т → 13700, 48 т → 13650) и метку «синтетический QA».
- Перезагрузка: квитанция у B читается снова; запрос виден у A и A2.
- A отвечает в приложении; B после перезагрузки видит ответ с автором и временем.
- Доказательство: идентификатор квитанции, скриншоты обеих сторон до и после перезагрузки, количество записей = 1.

## 3. Что требует кандидата, а что — фикстур
**Только настоящий локальный кандидат:** декодирование и воспроизведение медиа, раскладка на 5 ширинах, фокус и Esc, перезагрузка с сохранением, видимость запроса у A/A2/B, сокрытие цены по реальным правам.
**Можно на изолированных фикстурах:** истечение базиса, конфликт изменённого текста, повтор с тем же ключом, потерянный ответ сервера, отказ чтения товара, ошибки проверки полей, отказ в правах для C. Результаты фикстур подтверждают логику, но не заменяют проверку кандидата.

## 4. Отрицательные права и повторы без изменения защищённых данных
- **C** открывает квитанцию и ветку B ↔ A по прямой ссылке → «Нет доступа», без товара, суммы и имени. Только чтение, ничего не меняется.
- **Аноним** открывает ту же ссылку → вход, без утечки данных в заголовке страницы или в ответе.
- **B** пытается ответить от имени продавца (подмена роли в синтетической фикстуре) → отказ.
- **Сотрудник A без прав** (если он есть в фикстуре) видит ветку без поля ответа.
- **Проверка полей:** количество 10 т < MOQ 24, пустое сообщение, больше остатка 178 т → отдельные ошибки, ничего не отправлено (счётчик записей не растёт).
- **Неясный ответ:** обрыв после отправки → «Проверяем…» → чтение по ключу → одна квитанция.
- **Повтор с тем же ключом и тем же текстом** → та же квитанция. **С тем же ключом и другим текстом** → конфликт, текст пользователя не потерян.
- **Истёкший базис** (только фикстура) → отказ, не замена.
Права реальным пользователям не выдаются; для отрицательных случаев используются заранее созданные синтетические участники.
