# P1S — независимая верификация /account/company (read-only) и предлагаемые правки

Проверка выполнена без изменений кода. Ниже — расхождение по SHA и найденные дефекты
с предлагаемыми минимальными исправлениями. Реализация только после одобрения.

## Расхождение состояния (блокер чекпоинта)

Ожидаемый HEAD `556375526860938aa48d7e92ce14272a04d8044a` присутствует в истории ветки,
но текущий HEAD — `7404c532d1b526a3e67090b4dce3f97c059fa3ea` (на 3 коммита выше).
Между ними изменены `src/data/certifications.ts`, `src/i18n/translations.ts`,
`src/pages/account/Account.tsx`, `src/data/certifications.test.ts`.
Решение до Build: подтвердить, что верификация принимается на текущем HEAD, либо назвать новый ожидаемый SHA.

## Предлагаемые правки (только при одобрении)

1. `src/data/certifications.ts` — добавить ES-переопределение `name` для `HALAL` и `KOSHER`
   (`Halal` / `Kosher` -> `Halal` / `Kosher` подтвердить как нативные, либо `Cosher`),
   чтобы поле `name` не оставалось только EN-производным. Severity: Info.
2. Скриншот `desktop-edit-picker-open.png` обрезает открытый список, потому что
   `card.screenshot()` не включает absolute-позиционированный `listbox`. В
   `e2e/p1s-company-certifications.spec.ts` снимать область карточки + список
   (например, скриншот секции `account-section-company`), чтобы визуальное доказательство
   покрывало опции с логотипом и без. Severity: Warning (только доказательная база, не UI).

Вне scope: публичный SupplierProfile, каталог поставщиков, API/бэкенд, новые логотипы и пакеты.
